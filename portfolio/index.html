01 · 사이드 프로젝트 · 운영 중

OurBibleNote

성경 구절 간의 관계를 그래프로 시각화하고 QT 노트를 연결하는 웹 서비스입니다. 구약과 신약을 한 장의 지도로 보고, 연결된 장을 따라 읽으며 그룹과 묵상 노트를 남깁니다.

문제

성경은 구절이 서로를 가리키는데, 그 관계를 한 장의 지도로 보면서 묵상 노트까지 같은 자리에 두기가 어려웠습니다. 역본을 바꿔도 같은 자리가 이어져야 했습니다.

역할

혼자 기획부터 개발, 배포, 운영까지 맡았습니다.

기술

  • Django
  • DRF
  • Python
  • Next.js
  • React
  • TypeScript
  • PostgreSQL
  • Redis
  • Docker
  • GitHub Actions
  • Playwright

기술적으로 손댄 부분

  • Django 6 + DRF 백엔드(Python 3.14, uv)와 Next.js 15(App Router, React 19, TypeScript) 프론트엔드를 한 모노레포로 구성했습니다.
  • 성경 4개 역본(개역개정·개역한글·NIV·NLT)을 장 단위 그래프 노드로 구성하고, 노드·엣지·태그·그룹 공유 API를 설계했습니다.
  • Google·Kakao·Naver 소셜 로그인은 state 검증과 Django 세션 쿠키로 인증합니다.
  • 데이터 시딩은 멱등합니다. Excel에서 Bible 테이블을 거쳐 그래프 노드까지 이어집니다.
  • GitHub Actions에서 ruff·ty·마이그레이션 누락 검사·pytest(PostgreSQL)와 프론트 lint·tsc·Vitest·Playwright E2E를 돌립니다. E2E는 CSP 위반 0건을 확인합니다.
  • 홈서버에 Docker Compose로 운영합니다. PostgreSQL 18, Redis, 리버스 프록시, nonce 기반 CSP를 씁니다.
  • 에이전트용 가이드를 두고, lint·타입 검사·테스트·E2E를 CI로 강제해 도구가 작성한 코드도 같은 기준으로 검증합니다.

결과

  • https://ourbiblenote.com 에서 운영 중입니다.
  • 배포 전에 lint, 타입 검사, pytest, E2E가 통과해야 합니다.

링크

  • ourbiblenote.com

02 · 개인 인프라 · 진행 중

홈서버

집 Mac Mini로 개인 인프라와 배포를 직접 돌리는 작업입니다. 클라우드 콘솔을 흉내 내는 대신, 앱을 올렸다 내리고 저장소를 나누고 공개 면만 밖으로 냅니다.

문제

데이터베이스, 캐시, 파일 저장소, 프록시처럼 오래 남는 것과 자주 갈아끼우는 웹앱의 수명이 다릅니다. 데이터는 잘 안 건드리고 앱만 자주 바꾸고 싶었습니다.

역할

개인 인프라를 직접 구성하고 운영합니다. 인프라 저장소는 공개하지 않습니다.

기술

  • PostgreSQL
  • Redis
  • Docker
  • Colima
  • k3s
  • Cloudflare
  • Nginx Proxy Manager
  • Beszel
  • Uptime Kuma

기술적으로 손댄 부분

  • 오래 남는 것은 호스트 위 컨테이너로 두고, 웹앱은 Colima로 띄운 k3s에 올립니다.
  • 앱 저장소는 컨테이너 이미지만 만들고, 인프라 저장소가 그 이미지를 받아 올립니다.
  • 파일 저장소는 앱마다 접근 권한을 나눕니다. 관리자 계정은 앱에 넣지 않고, 관리 화면은 인터넷에 열지 않습니다.
  • 밖에 내보내는 앱은 공유기 포트를 열지 않고 Cloudflare Tunnel로 나갑니다. 인증서는 Nginx Proxy Manager에서 끊습니다.
  • 머신과 컨테이너 상태는 Beszel로, 서비스가 살아 있는지는 Uptime Kuma로 봅니다. 대시보드는 밖에 열지 않습니다.

결과

  • OurBibleNote를 이 구성 위에서 운영합니다.
  • 공개 면과 관리 면을 나눠, 대시보드와 관리 화면은 인터넷에 열지 않습니다.

링크

공개된 저장소나 제품 링크는 없습니다.

03 · 미피아 · 2025.10 – 2026.02, 이후 운영

음원 분석 API 플랫폼

외부 개발자용 음원 분석 API 플랫폼을 프로토타입에서 프로덕션으로 다시 설계하고 구축한 일입니다. 2025년 12월 16일 API v1.0을 공개한 뒤 같은 구조 위에서 버전을 늘리며 운영합니다.

문제

밖으로 내놓은 음원 분석 API가 프로토타입에 머물러, 외부 개발자가 그대로 붙이기 어려웠습니다.

역할

백엔드 개발자로 아키텍처 설계와 구축을 맡았습니다. 사실상 단독으로 진행했습니다.

기술

  • Python
  • SQL

기술적으로 손댄 부분

  • API v1.0은 AI 음악 판별(lite·standard·pro), 음악 표절 탐지, 가사 표절 분석, 데이터셋 관리, Webhook 연동을 제공합니다.
  • v1.1에서 가사 추출 API를 같은 구조 위에 올렸습니다 (2026.02).
  • v1.1.1은 음원을 먼저 올립니다. POST /api/v1/music 이후 musicId로 분석합니다.
  • 음원 fingerprint를 서버에 구현해 기능을 확장했습니다.

결과

  • 2025.12.16 API v1.0을 공개했습니다.
  • 이후 가사 추출, 선업로드, fingerprint까지 같은 플랫폼에서 운영합니다.
  • B2B 과금 체계(Credit Wallet) 전환도 이 플랫폼 위에서 이어집니다.

링크

  • docs.mippia.com
